# 발표용 더미 데이터 (200명) 설계

- 작성일: 2026-11-17 · 상태: 승인됨
- 관련: `2026-11-11-unity-session-dashboard-design.md`

## 목적

발표에서 대시보드를 꽉 찬 모습으로 보여 준다. 실제 서버(S3)에 더미 200명을 넣고, 이후 실제로 쏜 몇 명을 그 사이에 섞는다. 발표가 끝나면 더미만 지울 수 있어야 한다.

## 접근 방식

| 방식 | 판단 |
|---|---|
| **서버 상태에 직접 넣는 스크립트 (선택)** | 실제 기록과 같은 화면에 섞이고, 한 번에 저장해 빠르다 |
| 화면의 가짜 데이터 모드 | 실제로 쏜 사람이 섞이지 않아 목적과 맞지 않음 |
| HTTP로 세션 1,000번 전송 | 매번 state.json 을 통째로 다시 써서 느리고, 사람마다 배치를 바꿔야 함 |

## 결정

- 200명 = 10개 소대 × 20명. 이름·군번(`26-7xxxxxxx`)은 실제처럼, 기존 명단 군번과 겹치지 않게.
- 1인당 세션 2~8회, 실행 시각 기준 지난 30일 09~20시에 분포.
- 세션은 실제 유니티 세션과 같은 모양(Stage01 · IndoorTargetScore · 10m · 10발 · 총구 궤적 · 캔트 · MagazineEmpty)으로 만들어 서버의 `summarize`를 그대로 거친다 → 지표·클릭·합격이 실제와 같은 규칙으로 계산된다.
- 실력은 세션마다 좋아지고, 사람마다 약한 지표가 하나씩 있다 → 합격·미달이 섞이고 교정 포인트가 고르게 나온다.
- 더미 표시(`dummy: true`)는 상태(state.json)의 명단·세션에만 두고 화면 응답에는 넣지 않는다.
- 더미 세션의 원본은 S3 `raw/`에 쓰지 않는다 (요청 1,000번 절약, 삭제 권한 불필요). `recompute`는 더미 세션을 건너뛴다.
- 넣기는 기존 더미를 지우고 새로 만든다 → 발표 당일 다시 돌리면 날짜가 그날 기준이 된다.
- 지우기는 더미 명단·세션만 지운다. 실제 세션이 더미 사람에게 붙어 있었다면 미배정으로 돌리고, 더미 사람에게 걸린 시뮬레이터 배치도 해제한다.
- 서버가 상태를 메모리에 들고 있으므로 스크립트는 서버를 끈 상태에서 실행한다.

## 비목표

- 화면에서 더미를 구분해 보여 주기, 더미 인원 수를 화면에서 정하기
- 실제 사람의 기록을 더미로 만들어 넣기
